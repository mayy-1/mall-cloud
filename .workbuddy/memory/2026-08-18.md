## Redis 数据全景实测（回答"Redis 里存什么"）
- 直连 localhost:6379 db0 实测：共 53 个 key，分 6 类：
  - Sa-Token 会话 39 个（占 73%）：`Authorization:memberLogin:token:{uuid}`→memberId、`session:{id}`→SaSession JSON、`Authorization:login:*` 后台 admin；TTL≈30 天
  - 优惠券 6 个：`coupon:list:available`(30min)、`coupon:stock:{id}`(永久)、`coupon:users:{id}` Set(永久)、`coupon:history:{mid}:{type}`(600s)
  - 秒杀 5 个：`seckill:stock:14:*`（活动14 预热过但无 `seckill:users`/`prewarmed` → 秒杀链路尚未完整跑通）
  - 实体缓存 2 个：`mall:member:{id}` TTL 1 天；权限规则 1 个：`auth:pathResourceMap` Hash 31 fields
  - 框架配置 20 个：`sys_config:*`/`sys_dict:*`/`num` 若依风格遗留，非业务代码
- 关键结论：购物车/普通商品库存不在 Redis（走 MySQL lockStock）；全项目无 @Cacheable 注解，纯手动 Cache-Aside；key 命名两套并存（硬编码常量 vs yaml 前缀）。
- 可用工具脚本：`C:\Users\L\.workbuddy\binaries\python\envs\default\scan_redis.py`（redis-py protocol=2 兼容老版本 Redis）。

## Feign Header 透传全局化
- 根因：`mall-api/config/DefaultFeignConfig.java` 的 RequestInterceptor（透传 Authorization）早已存在，但 13 个 FeignClient 中仅 `MemberClient` 显式挂 `configuration = DefaultFeignConfig.class`，其余 12 个不生效 → 跨服务调用 token 丢失（NotLoginException）。
- 改动：
  1. `DefaultFeignConfig` 拦截器重构为白名单数组 `PASS_THROUGH_HEADERS = {"Authorization"}`，无 Servlet 上下文（MQ/定时任务）时安全放行。
  2. 9 个启动类 @EnableFeignClients 统一加 `defaultConfiguration = DefaultFeignConfig.class`：User/Cart/Marketing/Order/Member/Search/Trade/Product/Payment。
- 验证：mall-api/mall-common 离线编译通过；gateway 不依赖 mall-api、无 Feign，不受影响；memberId header 仅为 gateway 限流读取，非注入头，白名单无需扩展。
- 注意：`DefaultFeignConfig` 不能加 @Configuration（否则被组件扫描双重注册），保持普通类作为 defaultConfiguration 使用。

## 确认单 Feign 子线程 token 丢失修复（NotLoginException 深层根因）
- 现象：登录成功（Redis 有 token/session）但购买确认单仍报 `NotLoginException: 未能读取到有效 token`。
- 根因：`PortalOrderServiceImpl.generateConfirmOrder/buyNowConfirm` 用线程池 `orderConfirmExecutor` 并行查询，子线程里 `memberAddressClient.list()`（→ member-service `/member/address/list` → `AddressServiceImpl.list` → `getCurrentMember` 需要登录）发起 Feign 调用；但 `RequestContextHolder` 基于 ThreadLocal 不跨线程，拦截器在子线程拿不到 Authorization → 不传 token → member-service 抛 NotLoginException。
- 关键区分：`getIntegrationConsumeSetting`（/member/integrationConsumeSetting）不需要登录；报错点锁定在 memberAddressClient.list。
- 修复：
  1. mall-api 新增 `FeignAuthContext`（ThreadLocal 持有 token，set/get/clear）。
  2. `DefaultFeignConfig` 拦截器双通道取 token：优先 `FeignAuthContext.getToken()`，兜底 `RequestContextHolder` 的 Authorization；统一补 Bearer 前缀。
  3. `PortalOrderServiceImpl` 新增 `getCurrentToken()` + `asyncWithToken(Supplier)`（主线程取 token → 子线程 set → finally clear），替换确认单两处 6 个 supplyAsync。
- 全项目仅此一处 CompletableFuture.supplyAsync，无其他服务受影响。
- 提醒：order-service 未引入 Sa-Token，token 只能从 RequestContextHolder 拿；若后续其他服务也用线程池调 Feign，需同样用 FeignAuthContext 传 token。
- 已沉淀"Feign 异步调用丢失 Token"面试口述稿（背景→现象→根因→四步方案→结果 + 追问预案），可直接背诵，含 FeignAuthContext / 拦截器双通道 / asyncWithToken 三段代码卡片。

## 确认单价格=0 与积分设置 null 修复
- 现象：`buyNowConfirm`（立即购买确认单）返回 `price=0`、`realStock=null`、`calcAmount` 全 0、`integrationConsumeSetting=null`。
- 根因1（价格=0）：`buyNowConfirm` 只调 `buildBuyNowItem()`，该方法把 price 硬编码 `BigDecimal.ZERO`；对比 `buyNow`（下单）会先 `validateProduct` 查真实价格再 `setPrice(product.getPrice())` 覆盖，确认单漏了这一步。
- 修复1：`buyNowConfirm` 在 buildBuyNowItem 后补 `validateProduct(productId)` + `virtualItem.setPrice(product.getPrice())`（顺带在确认单阶段拦截下架商品）。
- 根因2（integrationConsumeSetting=null）：`MemberIntegrationController.getIntegrationConsumeSetting()` 返回裸 `UmsIntegrationConsumeSetting`，而 Feign 客户端声明 `CommonResult<IntegrationConsumeSettingDTO>`，JSON 结构不匹配 → data 反序列化为 null（表里其实有 id=1 数据）。
- 修复2：Controller 改返回 `CommonResult<UmsIntegrationConsumeSetting>`，用 `CommonResult.success(...)` 包装；字段名一致，Feign 自动映射到 DTO，无需 mall-api 依赖。
- realStock=null 是历史设计（确认单不查库存、下单时查），本次保持不变。
