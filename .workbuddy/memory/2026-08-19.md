## JVM 调优体检（针对内存泄漏清单逐条排查项目）
- 结论：项目代码层面内存泄漏风险几乎为零；最大调优空白是「完全没有 JVM 参数」+「Redis 永久 key 堆积」。
- 逐条体检：
  - ThreadLocal：仅 `FeignAuthContext`（已 finally clear）；Sa-Token/PageHelper 的 ThreadLocal 由框架管理。无风险。
  - 静态集合：无 static 集合字段（StpMemberUtil 里的 `public static List` 是方法返回类型，非字段）。
  - 线程池：仅 order-service `ThreadPoolConfig.orderConfirmExecutor`（core=2/max=4/queue=20/CallerRunsPolicy/keepAlive30s），有界队列+拒绝策略，规范无泄漏，但容量偏小（性能项）。
  - IO/连接：MyBatis/Druid/RabbitMQ 框架管理。
  - 缓存：Redis 有永久 key 隐患 —— `coupon:stock/users:{id}`、`seckill:stock/users:{id}` 无 TTL，活动结束后不清理会堆积。
- JVM 参数：全项目搜不到 `-Xmx/-Xms/-XX:`，服务用 JVM 默认堆（IDEA 直接 run，无 Dockerfile/启动脚本）。
- 调优建议已给出：按服务分档配堆（轻服务 256m/512m、重服务 512m/1g）+ 统一 OOM dump 参数 + G1 调优；Redis 永久 key 加清理任务；线程池可调 core=4/max=8/queue=50。
